# Photography Portfolio

A minimal, fast photography portfolio built with [Astro](https://astro.build).
Grid gallery, keyboard-friendly lightbox, and automatic light/dark mode.

- **Grid gallery** with a lightbox (arrow keys, click-to-close, swipe on touch)
- **Work, About & Contact** pages with a responsive mobile menu
- **Contact form** that posts to any endpoint (e.g. Formspree) or falls back to email
- **Light & dark theme** that follows your system and remembers your choice
- **Responsive** masonry layout that keeps each photo's natural aspect ratio
- **Optimised images** — Astro generates responsive `webp` sizes at build time
- **Zero client framework** — tiny vanilla JS for the lightbox, menu and form

---

## Quick start

```sh
npm install       # install dependencies
npm run dev       # start dev server at http://localhost:4321
npm run build     # build the production site to ./dist
npm run preview   # preview the production build locally
```

> The project ships with **placeholder images** so it runs immediately.
> Replace them with your own (see below).

## Adding or replacing photos

1. **Drop your image** into `src/assets/photos/`
   (`.jpg`, `.jpeg`, `.png`, `.webp`, or `.avif`).
2. **Add an entry** for it in [`src/data/photos.ts`](src/data/photos.ts):

   ```ts
   {
     file: 'my-photo.jpg',      // exact filename in src/assets/photos/
     title: 'My Photo',         // shown in the gallery + lightbox
     date: '2025-07-01',        // ISO date — used for sorting (newest first)
     alt: 'Description for accessibility / SEO',
     location: 'Somewhere',      // optional
   }
   ```

Photos are sorted automatically, newest first.

Only list files that exist — the build fails fast with a clear error if a
filename doesn't match, so nothing silently goes missing.

### Removing the placeholders

The starter images are generated by `scripts/generate-placeholders.mjs`. Once
you've added your own photos:

1. Delete the placeholder files from `src/assets/photos/`.
2. Delete their entries from `src/data/photos.ts`.
3. Optionally delete `scripts/generate-placeholders.mjs` and remove the
   `"placeholders"` script from `package.json`.

## Customising the site

All the text lives in [`src/config.ts`](src/config.ts):

```ts
export const site = {
  name: 'Your Name',
  title: 'Your Name · Photography',
  description: 'A personal photography portfolio…',
  tagline: 'Photographs of light, land, and quiet moments.',
  email: 'hello@example.com',
  nav: [
    { label: 'Work', href: '' },
    { label: 'About', href: 'about' },
    { label: 'Contact', href: 'contact' },
  ],
  contact: { endpoint: '' }, // see “Contact form” below
};
```

Design tokens (colours, spacing, radius, max width) are CSS custom properties
at the top of [`src/styles/global.css`](src/styles/global.css). The light and
dark palettes are defined under `:root` and `:root[data-theme='dark']`.

## Pages

- **Work** — `src/pages/index.astro`, the gallery.
- **About** — `src/pages/about.astro`. Edit the `bio` array at the top of the
  file and replace `src/assets/portrait.jpg` with your own picture.
- **Contact** — `src/pages/contact.astro`, the contact form.

Navigation is driven by `site.nav` in `src/config.ts` — add, remove, or reorder
entries there. `href` is a path relative to the site base (`''` = home).

## Contact form

The form posts to **any endpoint that accepts a `POST`**. The easiest option is
[Formspree](https://formspree.io) (there's a free tier):

1. Create a form on Formspree and copy the endpoint, e.g.
   `https://formspree.io/f/abcdwxyz`.
2. Set it in `src/config.ts`:

   ```ts
   contact: {
     introduction: 'I’d love to hear from you…',
     endpoint: 'https://formspree.io/f/abcdwxyz',
   },
   ```

**No endpoint?** The form gracefully falls back to opening the visitor's email
app with their message pre-filled, so contact still works out of the box. A
hidden honeypot field helps cut down on spam.

## Deployment

### GitHub Pages (automatic)

A workflow is included at
[`.github/workflows/deploy.yml`](.github/workflows/deploy.yml). It builds and
deploys the site on every push to `main`.

1. **Create a repository on GitHub** and push this project to it:

   ```sh
   git init
   git add -A
   git commit -m "Initial commit"
   git branch -M main
   git remote add origin https://github.com/<user>/<repo>.git
   git push -u origin main
   ```

2. **Enable Pages** in your repo: **Settings → Pages → Build and deployment →
   Source → GitHub Actions**.

3. Push to `main` (or run the workflow manually from the **Actions** tab). Your
   site will be published at:

   - `https://<user>.github.io/` for a repository named `<user>.github.io`
   - `https://<user>.github.io/<repo>/` for any other repository

You don't need to edit the config for either case — the correct `site` and
`base` are detected from the repository automatically during the build.

### Custom domain

If you're using a custom domain, set the environment variables in the build
step of `.github/workflows/deploy.yml` (there's a commented example in the
file) and add a `CNAME` file to `public/` containing your domain:

```yaml
- name: Build with Astro
  uses: withastro/action@v6
  env:
    SITE_URL: https://your-domain.com
    BASE_PATH: /
```

## Tips for best results

- **Export photos around 2000–2500px on the long edge.** Astro resizes
  down to the sizes it needs, so originals don't need to be huge — but they
  should be at least as large as the largest size you'll display.
- **Write meaningful `alt` text.** It helps screen-reader users and SEO.
- **Keep filenames lowercase-with-dashes** (e.g. `golden-fields.jpg`).
